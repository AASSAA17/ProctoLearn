# Локальный AI и прокторинг

## Реализованная граница

`POST /ai/chat` сохраняет DTO `{ message, history?, courseId? }` и ответ `{ reply }`. JWT, ограничение частоты и серверная проверка сессии применяются как раньше. Браузер обращается только к backend. Groq и база ответов по ключевым словам удалены: если локальный сервис выключен/недоступен, ответ прямо сообщает об этом. Модель не заменяет записи приложения и решения преподавателя/проктора.

Backend использует нативный Ollama `POST /api/chat`, `stream: false`. Отдельной общей истории на сервере нет: в запросе до шести реплик по 2000 символов. Клиент очищает историю при смене аккаунта, отменяет текущий HTTP-запрос и отвергает запоздалые ответы старой сессии. При разрыве соединения backend отменяет запрос к модели.

Локальный endpoint задаётся оператором, разрешены только loopback и фиксированные имена локального контейнерного окружения. Редиректы запрещены. Параметры модели/URL не принимаются от пользователя или инструмента. Явные cloud-модели отвергаются. На процессе Ollama дополнительно необходим `OLLAMA_NO_CLOUD=1`; это отдельная настройка сервера модели, не переменная браузера.

## Ограничения ресурсов

- Одна генерация на процесс API; очередь приложения — ноль. Следующий запрос сразу получает сообщение о занятости.
- Общий бюджет до 120 секунд на запрос, включая раунды инструментов. `OLLAMA_TIMEOUT_MS` может уменьшить его; верхняя граница 120000 мс. Клиентский лимит только чата — 125 секунд.
- Контекст: не более 32000 символов сериализованных сообщений, окно модели 8192 токена; генерация до 1500 токенов, температура 0.2.
- Не более двух раундов инструментов, четырёх вызовов суммарно и одного финального запроса без описаний инструментов.
- HTTP-ответ провайдера до 65536 байт, текст ответа до 6000 символов. Невалидный JSON, незавершённая/обрезанная генерация, некорректные вызовы и таймаут дают безопасное сообщение о недоступности.
- В установленном шаблоне Qwen3 `think: false` возвращал рассуждения вместо финального ответа. Интеграция использует `think: true`, принимает только финальный `content` и отбрасывает `thinking`; совместимость со старым форматом дополнительно удаляет префикс до `</think>`. Незакрытый блок отвергается.

Эти ограничения ограничивают нагрузку, но не гарантируют качественный ответ маленькой модели на каждый вопрос. Длинная история может закончиться сообщением о недоступности вместо скрытого расширения контекста.

## Инструменты только для чтения

| Имя | Серверная область | Возвращаемые данные |
| --- | --- | --- |
| `my_courses` | Записи Enrollment текущего пользователя | До 10 ID/названий/уровней курсов и отметка завершения |
| `my_progress` | Только свой прогресс в курсе с собственной записью Enrollment | Число уроков обоих путей и число корректно завершённых уроков |
| `course_outline` | Запись Enrollment или собственный `teacherId` | До 20 названий и порядка уроков/модулей; без содержимого и решений |
| `my_results` | Только свои попытки с `finishedAt != null` | До 5 результатов, балл, фактический статус попытки и отдельный статус проверки |
| `my_certificates` | Только свои сертификаты | До 5 ID, дат, статусов, отметок отзыва и сохранённых при выдаче реквизитов со статусом snapshot; отсутствующие исторические значения остаются null |

Аргументы проверяются во время выполнения, а не только объявляются в JSON Schema. Разрешён лишь `courseId` у двух инструментов; `userId`, роль, SQL, адреса, пути и неизвестные имена не принимаются. Даже администратор через AI не получает чужие записи. Отсутствующий и запрещённый курс возвращают одинаковую ошибку. Ни один запрос не выбирает пароли, ответы экзамена, `assignmentAnswer`, JSON заданий, записи камеры, signed URL или QR-коды.

Прогресс учитывает новые правила завершения: строка просмотра старого задания не считается выполнением, если у урока есть приватное решение, а источник завершения не `ASSIGNMENT`. Уроки напрямую в курсе и уроки через модуль учитываются вместе.

При любой своей незавершённой попытке (`finishedAt = null`, `IN_PROGRESS` или `FLAGGED`) сервер возвращает 403. Проверка повторяется перед генерацией, перед каждым инструментом и перед выдачей результата. Даже истёкшая по времени попытка блокирует чат до авторитетного завершения её состояния. Виджет по-прежнему скрыт на маршруте экзамена.

## Безопасность и отказ

Текст и результаты инструментов считаются недоверенными. Содержание курса не может расширить права инструментов. Модель не имеет соединения с БД, файловой системой или shell; backend выполняет только явно написанные read-only Prisma-запросы.

Виджет не исполняет HTML, не загружает картинки и не превращает ссылки модели в внешние действия. Ответы и ошибки провайдера, история и заголовки не пишутся в лог. Краткое предупреждение `Local AI request unavailable` не содержит персональных данных. Индикатор больше не утверждает, что модель «онлайн», без проверки.

AI не входит в зависимости `/health` или `/ready` и не участвует в транзакциях оценки/сертификатов. Ошибка чата не изменяет оценку или сертификат.

## Проверки и реальные ограничения

Детерминированные тесты: `npm run test:ai` в backend; настоящий локальный HTTP-сервер имитирует Ollama 500, неверный JSON, неверный tool call, слишком большой ответ, обрезанный ответ, таймаут, отключение клиента и перегрузку. Также проверяются сессии, запрет экзамена и ограничение раундов.

PostgreSQL: `test/integration/ai-access.test.cjs` использует только защищённую disposable БД `proctolearn_security_test`. Проверяет реальные отношения курса/уроков, межпользовательские запреты, отсутствие решений, review/status, отозванный сертификат и запрет активной попытки.

Отказ провайдера в работающем API: `test/integration/ai-core-isolation.cjs` запускается отдельно от CI, только через работающий изолированный release-профиль. Команда PowerShell из корня репозитория:

```powershell
$env:RUN_AI_CORE_ISOLATION='1'
node scripts/demo-release.cjs exec backend test/integration/ai-core-isolation.cjs
```

Тест проверяет свободные порты, запускает собственный API на `127.0.0.1:4001` с Ollama endpoint `127.0.0.1:11436`, где подтверждён `ECONNREFUSED`. Через настоящий CSRF/register создаётся уникальный вымышленный студент. Проверяются явная недоступность `/ai/chat`, а также `/ready` и публичный `/courses` до, одновременно с запросом и после него. В `finally` останавливается только собственный API и удаляется только созданный пользователь. Пароли, cookies и приватный environment не выводятся. Тест не останавливает установленный Ollama и не проверяет обучение или выдачу сертификата во время отказа.

Реальная модель: `test/integration/ai-local-model.cjs` запускается только с `RUN_LOCAL_AI=1`, использует настоящую БД и уже установленные веса. Проверяет русский, казахский, вызов `my_courses` и запрещённый контекст. Это отдельный запуск; mock-тесты не являются доказательством качества модели. Актуальные PASS/FAIL и времена следует брать из `TEST_RESULTS.md` и результата этого запуска.

Настройка, проверенное оборудование и ограничения модели описаны в [AI_LOCAL_SETUP.md](AI_LOCAL_SETUP.md).

Это режим демонстрации, а не заявление об исправленной модели. Детерминированные AI-тесты повторно 12 PASS, реальный PostgreSQL scope-тест PASS; эти проверки не заменяют качество модели.

## Прокторинг

Камера и экран записываются. Браузер сообщает о переключении вкладки, копировании/вставке, выходе из полного экрана и остановке демонстрации экрана. Trust Score рассчитывается по этим событиям; назначенный проктор принимает решение, предусмотрена апелляция.

Нет детектора лица/телефона, идентификации личности по видео или измеренной доли ложных срабатываний. Trust Score не доказывает мошенничество. Этот релиз не добавляет AI-оценку честности или автоматическое изменение оценок.
