# Локальный Ollama для демонстрации

Проверено 10 октября 2026: Windows, Ollama 0.40.2, установленные `qwen3:4b` Q4_K_M, 16.89 GB RAM, NVIDIA GeForce RTX 3050 Laptop GPU 4096 MiB VRAM. Порт 11434 слушал только `127.0.0.1`. Новые веса не скачивались. Это конкретная конфигурация проверки, не минимальные аппаратные требования.

## Настройка

На процессе Ollama задайте локальный режим. Если Ollama уже работает как desktop-приложение, сначала завершите его через меню приложения; не запускайте второй экземпляр на том же порту.

```powershell
$env:OLLAMA_HOST = '127.0.0.1:11434'
$env:OLLAMA_NO_CLOUD = '1'
$env:OLLAMA_NUM_PARALLEL = '1'
ollama serve
```

Эти значения относятся к процессу Ollama. Установка `OLLAMA_NO_CLOUD` только в окружении API не меняет уже запущенный сервер модели. Не публикуйте 11434 через firewall/tunnel/reverse proxy. Для локального desktop-приложения оператор может задать эти переменные перед его запуском. Фактический режим cloud-off необходимо подтвердить по локальному журналу `Ollama cloud disabled: true`.

В приватной конфигурации backend:

```dotenv
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:4b
OLLAMA_TIMEOUT_MS=120000
```

Отсутствующий или другой `AI_PROVIDER` выключает генерацию. Нет переключения на облако. В браузер эти переменные не передаются. Сохраняйте приватную конфигурацию в предусмотренном launcher месте и не коммитьте её. Перезапустите API штатным launcher после изменения окружения.

Проверка установленной модели, без скачивания:

```powershell
Invoke-RestMethod http://127.0.0.1:11434/api/version
Invoke-RestMethod http://127.0.0.1:11434/api/tags
Invoke-RestMethod http://127.0.0.1:11434/api/ps
```

Первое обращение может загружать модель в память существенно дольше последующих. Ограничение 120 секунд сохраняется и в этом случае; интерфейс показывает понятный отказ. Модель может использовать CPU и GPU одновременно. Окно 8192 и генерация до 1500 токенов выбраны из-за потребности установленной модели отделять рассуждения от ответа; это не обещание мгновенной генерации.

## Тесты

Из корня проекта после старта disposable test fixture:

```powershell
node scripts/demo-release-tests.cjs exec backend --require ts-node/register test/integration/ai-access.test.cjs
$env:RUN_LOCAL_AI = '1'
node scripts/demo-release-tests.cjs exec backend --require ts-node/register test/integration/ai-local-model.cjs
```

Второй тест может выполняться несколько минут: четыре независимых обращения к реальной модели. Он не запускает загрузку весов и не нужен обычному CI. Создаёт свои временные записи в проверенной disposable БД и удаляет только их. Нельзя подменять его успешность результатами fake HTTP теста.

Для отдельного оставшегося сценария можно явно задать `AI_TEST_CASES=LOOKUP,FORBIDDEN_CONTEXT` (или одну из `RU`, `KK`, `LOOKUP`, `FORBIDDEN_CONTEXT`). Тест печатает выбранные и исключённые проверки. Успех выбранного подмножества не означает успех полного AI acceptance.

### Измеренные ограничения

Полный service-run 10 октября 2026: русский ответ PASS за 44.443 с, казахский — FAIL по общему лимиту 120 с. Отдельный LOOKUP-run также завершился безопасной недоступностью за 120.14 с. Отдельный `FORBIDDEN_CONTEXT` — PASS за 60.085 с: backend-инструмент вернул `NOT_FOUND_OR_FORBIDDEN`, модель отказала в показе курса. Название чужого курса в ответ не попало. Это не заменяет неуспешный authorized lookup.

Проверены две дополнительные конфигурации напрямую через нативный `/api/chat`, без БД и без замены настроек приложения:

| Конфигурация | Наблюдение |
| --- | --- |
| 8192 (рабочая конфигурация сервиса) | `/api/ps`: 4.13 GB суммарно, 2.39 GB VRAM; часть модели на CPU |
| 4096, `num_gpu=99`, температура 0.2, лимит 1500 | Полностью GPU: 3.178 GB. Казахский вопрос: 39.82 с, `done_reason=length`, финальный ответ пуст |
| 4096, `num_gpu=99`, температура 0.6, лимит 2048 | Казахский вопрос: 37.55 с, `done_reason=length`, финальный ответ пуст |

Меньшее окно устранило часть аппаратной задержки, но обе ограниченные попытки потратили бюджет на reasoning без ответа. Поэтому настройки приложения не заменены этими экспериментами. Новые веса не загружались, AI_DEMO_BLOCKED сохраняется. Проблема требует отдельного выбора/проверки пригодной модели, а не неограниченных повторов или готового текста вместо генерации.

## Исследование шаблона установленной модели

`qwen3:4b` с `think: false` возвращала рассуждения в поле content. Вариант с явным `/no_think` тоже не дал корректного финального ответа в коротком лимите. Создан один отдельный alias `proctolearn-qwen3:4b` из тех же весов для проверки закрытого thinking-префикса; оригинал не изменён. Alias не используется по умолчанию: эксперимент не устранил поведение модели.

Воспроизводимый эксперимент (запускайте только если хотите повторить; он создаёт/обновляет именно этот экспериментальный alias):

```powershell
$source = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:11434/api/show -ContentType 'application/json' -Body '{"model":"qwen3:4b"}'
$needle = '<|im_start|>assistant' + "`n<think>`n{{ end }}"
if (!$source.template.Contains($needle)) { throw 'Unexpected model template' }
$template = $source.template.Replace($needle, '<|im_start|>assistant' + "`n<think>`n</think>`n`n{{ end }}")
$body = @{ model='proctolearn-qwen3:4b'; from='qwen3:4b'; template=$template; stream=$false } | ConvertTo-Json -Depth 6
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:11434/api/create -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
```

Используемая интеграция включает отделение reasoning в исходной модели (`think: true`), не возвращает эту часть пользователю и отвергает незавершённый результат. Полезность русских/казахских ответов и инструментов требует отдельного real-model запуска, описанного выше.

Официальные контракты: [chat](https://docs.ollama.com/api/chat), [создание локального alias](https://docs.ollama.com/api/create), [локальный режим и привязка интерфейса](https://docs.ollama.com/faq). Конфигурация Ollama и её template могут меняться; при смене модели повторите настоящую проверку, не копируйте старый статус готовности.

## Повторная диагностика оставшегося gate — 10 октября 2026

База проверки: `19cd99e73afa2b9017ec0a93c539ad053e0eb13e`, ветка `fix/demo-remaining-gates-20261010`, плюс диагностический скрипт текущих изменений. Production provider не изменён. Использована отдельная БД `proctolearn_security_test` на 55432, только собственные временные вымышленные записи. Demo-профиль не сбрасывался.

Свежие `/api/version`, `/api/show`, `/api/tags`, `/api/ps` подтвердили:

- Ollama `0.40.2`, `qwen3:4b`, Q4_K_M, 4.0B, GGUF; digest `359d7dd4bcdab3d86b87d73ac27966f4dbb9f5efdfcc75d34a8764a09474fae7`.
- `general.finetune=Thinking`, `thinking.values=[true]`, default `true`; capabilities `completion,tools,thinking`. Эта установленная модель разрешает только thinking-режим, несмотря на короткий tag `qwen3:4b`. Отключение reasoning не считается поддерживаемым исправлением. [Официальный контракт discovery thinking controls](https://docs.ollama.com/capabilities/thinking).
- Объявленный контекст весов 262144; реально выделенный контекст процесса зависит от `num_ctx`. SHA-256 шаблона `2d54db2b9bb29ce7db54fea63a891f5859603813c555b1f88b5e0994652897f9`; его финальный assistant-префикс открывает `<think>`. Шаблон не менялся.
- Установлены только исходная модель и прежний экспериментальный alias; других подходящих весов нет. До первого запроса `/api/ps` был пуст — это действительно холодная загрузка. Слушатель 11434 остаётся на `127.0.0.1`; cloud-off окружение существующего процесса повторно не подтверждено.

`backend/test/integration/ai-gates-diagnostic.cjs` собирает только операционные длительности/счётчики, имена разрешённых инструментов и короткие финальные ответы на публичные языковые вопросы. Ни raw thinking, ни приватные prompts/записи/credentials не выводятся. Все запросы последовательны; очередь приложения нулевая, общий deadline по-прежнему 120000 мс. Время очереди внутри Ollama не имеет отдельного подтверждённого счётчика; его нельзя выдавать за измеренную нулевую очередь сервера модели.

Длинная история/большой tool payload в меньшем окне этим тестом не сертифицируются.

Во всех завершённых генерациях кандидата `done_reason=stop`; непустой финальный ответ отделён от reasoning. RU-ответы правильно называли HTML языком разметки. Это фактический слабый ответ, а не таймаут. Остальные два кратких KK-ответа прошли минимальный языковой/семантический критерий, но не являются широкой оценкой педагогического качества. Успешный одиночный ответ не заменяет все три повтора.

Каждый LOOKUP реально вызвал `my_courses`: выбор инструмента занял первый model turn, запрос PostgreSQL — соответственно 11/1/1 мс, формирование ответа — второй model turn. Получено точное название собственного временного курса. FORBIDDEN_CONTEXT выполнил `course_outline` за 4 мс, получил `NOT_FOUND_OR_FORBIDDEN`; приватное название не раскрыто. Для unavailable подтверждён свободный 11436 и явный безопасный ответ AiService; установленный Ollama не останавливался. Полная сумма сценариев кандидата — 224.171 с; script exit 1 и итог `AI_DEMO_BLOCKED` из-за KK №2.

Кандидат полностью размещался в GPU: 3,178,149,969 байт `size=size_vram`, контекст 4096. RU №1 был **reload при смене параметров**, а не второй независимый cold boot; только исходный baseline начинался с пустого `/api/ps`. Повторы warm занимали от 6.199 до 47.914 с. Даже там, где ответ корректен и внутри 120 с, такую задержку следует отдельно считать ограничением удобства.

**Решение:** кандидат не перенесён в рабочий provider; 8192/1500/temp0.2 и граница доступа сохранены. Полный AI gate не закрыт. Для живой демонстрации используйте поддерживаемый launcher с `$env:DEMO_AI_PROVIDER='off'` перед запуском `node scripts/demo-release.cjs start`; это отдельная настройка процесса API, не остановка Ollama. При уже работающем demo сначала согласованно остановите его штатным `stop`, сохранив данные. Курсы, экзамены, review и сертификаты демонстрируются независимо от чата; отключённый чат сообщает о своём состоянии. Не включайте модель в обещанный сценарий без нового полного качества/времени acceptance.

Регрессии этой проверки: `backend/test/ai-chat.test.cjs` — 12 PASS; отдельный PostgreSQL `ai-access.test.cjs` — PASS (449.897 мс). Runtime AI-файлы не менялись. Инвентаризация, baseline и candidate выполнялись один раз каждый; дальнейшие model experiments остановлены после отрицательного полного результата.
