# ProctoLearn: демонстрационный запуск

Поддерживаемый путь этой поставки: Windows, Node.js 24.15+ LTS, PostgreSQL 16+ с установленными клиентскими утилитами (проверяемое окружение использует PostgreSQL 18), локальный SeaweedFS с приватным S3. Docker/WSL для этого пути не нужны. Запускайте команды из корня репозитория в PowerShell. Приложение открывается по `http://localhost:3000`, API — `http://localhost:4000`.

## Отдельные данные

`scripts/demo-release.cjs` создаёт профиль `.local/release-demo/`, собственный кластер `postgres/`, каталог `storage/`, БД `proctolearn_release` и bucket `proctolearn-release`. Старые `.env`, `.env.local`, `.local/postgres`, `.local/storage` и учётные записи прежнего запуска не используются. Каталог должен быть новым/пустым либо иметь маркер `ownership.json` данного профиля. Каталог с неизвестными данными отклоняется.

Пароли и ключи генерируются один раз. Повторная подготовка/запуск не меняет существующие пароли, контент, прогресс или результаты. Нет команды reset. Остановка сохраняет данные. Не удаляйте каталог профиля, чтобы «починить» запуск.

## Prepare / start / check / stop

Перед первым запуском проверьте `node --version`; Node должен быть доступен в PATH. PostgreSQL устанавливается отдельно владельцем машины; launcher не меняет службы/драйверы. Если установлено несколько версий, можно явно задать `$env:POSTGRES_BIN = 'C:\Program Files\PostgreSQL\18\bin'`. Версия бинарных файлов должна совпадать с версией уже созданного кластера.

```powershell
node scripts/demo-release.cjs prepare
node scripts/demo-release.cjs start --build
```

Первый `start --build` устанавливает зависимости строго через `npm ci`, генерирует Prisma client, собирает backend/frontend, применяет сохранённые миграции через `prisma migrate deploy` и создаёт маленький демо курс. Устанавливаемый npm и SeaweedFS сохраняются в `.local/tools`; загрузки проверяются по закреплённым checksum. Нужны сеть для первого получения зависимостей/инструментов и минимум 1 GiB свободного места (для видео/резервных копий нужно больше). Подготовленный оригинальный видеоклип хранится в `frontend/public/demo/`; при намеренном обновлении его источника используйте `node scripts/demo-release-media.cjs` в окружении с Playwright Chromium. Генератор сохраняет уже существующий клип.

Оставьте терминал запуска открытым. Во втором терминале:

```powershell
node scripts/demo-release.cjs check
node scripts/demo-release.cjs stop
```

`stop` обращается только к supervisor этого профиля через локальный request-файл. Он завершает принадлежащие ему процессы и выполняет штатную остановку PostgreSQL; данные остаются. Сторонние процессы принудительно не останавливаются. Повторный запуск готовой сборки:

```powershell
node scripts/demo-release.cjs start
```

После изменения исходников используйте `start --build`. Не запускайте две копии на одинаковых портах. Launcher проверяет loopback-порты 3000, 4000, 5433, 9000 и служебные порты SeaweedFS; при конфликте он сообщает об ошибке. База, storage и API привязаны к `127.0.0.1`. Логи — приватный каталог `.local/release-demo/logs`. `check` проверяет реальную HTTP readiness, но не является полным E2E.

## Доступы и оригинальный курс

Файл `.local/release-demo/DEMO_ACCESS.txt` содержит восемь вымышленных аккаунтов; не прикладывайте его к Git, отчётам или переписке. Роли и назначение:

| Email (вымышленный) | Сценарий |
|---|---|
| admin@demo.proctolearn.test | Управление и отзыв отдельного демо сертификата |
| teacher@demo.proctolearn.test | Владелец демо курса |
| teacher-other@demo.proctolearn.test | Проверка отказа в изменении чужого курса |
| proctor@demo.proctolearn.test | Первичная проверка |
| proctor-appeal@demo.proctolearn.test | Независимый разбор апелляции |
| student-new@demo.proctolearn.test | Запись и обучение с начала |
| student-progress@demo.proctolearn.test | Подготовка состояния с незавершённым заданием |
| student-result@demo.proctolearn.test | Подготовка результата и сертификата |

Аккаунты создаются без подставленных результатов. Сценарии progress/result необходимо подготовить реальными действиями приложения или принятым E2E. Seed не присваивает завершённый прогресс, баллы, одобрение или сертификаты напрямую.

Курс «Веб-әзірлеу негіздері — демонстрациялық курс» имеет стабильный ID `demo-release-web-foundations-v1`. Он содержит два модуля и пять уроков: структура HTML; короткий оригинальный клип с текстовой альтернативой; семантика и доступность; CSS; автоматически проверяемая практика. Экзамен `demo-release-web-exam-v1`: восемь вопросов SINGLE_CHOICE, MULTIPLE_CHOICE и TEXT, 3 минуты, порог 75%. Составные ответы оцениваются целиком; все вопросы имеют одинаковый вес по действующему механизму. Два проктора назначены для независимой апелляции. Ключи ответов находятся в backend seed/БД и не входят в публичные медиа.

Это подготовленный опубликованный авторский пример, а не доказательство ручной публикации. Проверка редактора/публикации выполняется отдельно. Seed создаёт весь курс транзакционно один раз; при дальнейших запусках даже удалённые учителем уроки не восстанавливаются автоматически. Видео — 12-секундная иллюстрация структуры HTML, без аудио, не полноценная лекция. Происхождение и транскрипт: `frontend/public/demo/PROVENANCE.txt`. Полные лекции и расширенный каталог относятся к Phase B.

## Окно обслуживания, backup и restore

Остановите приложение и запустите только его PostgreSQL/S3:

```powershell
node scripts/demo-release.cjs stop
node scripts/demo-release.cjs maintenance
```

В другом терминале, пока maintenance работает:

```powershell
node scripts/demo-release.cjs check
node scripts/demo-release.cjs backup rehearsal-01
node scripts/demo-release.cjs restore rehearsal-01
node scripts/demo-release.cjs stop
node scripts/demo-release.cjs start
```

Backup создаёт новый приватный каталог `.local/release-demo/backups/rehearsal-01`; повторное имя отклоняется. Restore создаёт новую пустую БД `release_restore_<random>` и отдельный bucket `release-restore-<random>` в том же выделенном профиле, проверяет отсутствие анонимного доступа и восстанавливает данные штатным `backup-cli.cjs`. Он не заменяет действующий профиль. Дамп, число строк, ссылки на объекты и SHA256 каждого объекта сверяются. Приватный `restore-<random>.json` сохраняет названия целей и результат. При ошибке частично созданные цели сохраняются для диагностики; повторный запуск получает другую пару. Подробные гарантии и ограничения — `docs/BACKUP_RESTORE.md`.

Для проверки восстановленного приложения после `stop` используйте `node scripts/demo-release.cjs start-restored restore-<suffix>.json`, подставив точное имя выданного приватного restore record. Команда принимает только помеченную успешно проверенную пару, не запускает seed и открывает её на привычных localhost-портах. Войдите прежними вымышленными доступами, проверьте урок/результат/сертификат и запись. Затем `stop` и обычный `start` возвращают исходный демо профиль. Это отдельная проверка usability поверх checksum/инвентаря; не объявляйте её выполненной до реального входа.

Для восстановления нужна сборка того же зафиксированного release snapshot, включая отслеживаемый `frontend/public/demo/html-structure.webm`. Backup содержит БД и объекты S3, но не исходники, сборку, модель Ollama или приватную конфигурацию. Приватные настройки сохраняйте отдельно в защищённом месте; потеря config/accounts при существующем кластере блокирует автоматическую генерацию новых несовпадающих доступов.

Release wrapper дополнительно сохраняет конфигурацию, вымышленные доступы, ownership marker и доступные отчёты сертификата/оригинального сценария в соседний приватный каталог `<backup>-operator`. Его `operator-manifest.json` содержит SHA256 файлов. Он отделён от проверяемого DB/S3 archive и тоже содержит секреты: переносите оба каталога только в защищённое хранилище. На Windows приватность определяется ACL родительского каталога.

После запуска восстановленной пары автоматическую браузерную проверку выполните командой `node scripts/demo-release-restore-smoke.cjs`. Она использует приватный отчёт оригинального сценария и проверяет вход, пять завершённых уроков, результат, PDF/QR и реальное воспроизведение обоих синтетических потоков из восстановленного bucket; анонимный GET должен возвращать403. Результат — `.local/release-demo/evidence/restored-smoke.json`. При необходимости задайте `E2E_CHROME_PATH`.

## Репетиция 8–10 минут

1. Откройте публичный каталог и объясните связь обучения, экзамена и QR-проверки.
2. Войдите преподавателем, измените демо урок; покажите явную публикацию отдельного учебного черновика.
3. Войдите подготовленным student-progress, завершите оставшуюся практику и покажите сохранение прогресса.
4. Начните трёхминутный экзамен; покажите предварительную проверку камеры/экрана и сохранение ответов.
5. Назначенным проктором откройте настоящую запись и вынесите решение с причиной.
6. Студентом скачайте сертификат. Откройте публичный QR verifier без входа.
7. Для телефона используйте только заранее согласованный доступный origin. `localhost` телефона не ведёт на ноутбук.
8. Администратором отзовите специально выбранный демонстрационный сертификат и повторно откройте тот же QR.
9. Показывайте AI только после отдельной проверки реального Ollama. Объясните read-only полномочия и независимость результата экзамена от AI.
10. Покажите фактический отчёт проверок. Подготовленные состояния и запись репетиции обозначайте явно.

## Сеть, почта и ограничения

Ноутбук использует localhost, допустимый для browser camera/screen API. Автоматическое открытие firewall, создание туннелей и публикация в интернете не выполняются. Публичный QR origin задаётся перед запуском через `DEMO_PUBLIC_APP_URL` только для заранее разрешённого HTTPS/private-network адреса. Проверка физическим телефоном требует отдельной реальной репетиции; синтетический браузер её не доказывает.

Release профиль запускает собственный mail catcher на SMTP localhost:1025 и веб-просмотр localhost:8025 (локальная демонстрационная доставка), а AI обращается к Ollama localhost:11434 / `qwen3:4b`. Письма не уходят в интернет; catcher завершается вместе с приложением. Наличие модели проверяется отдельно до репетиции. AI может быть недоступен без нарушения базового `/ready`. Внешние CDN/видео демо курсу не нужны; первоначальная установка зависимостей, загрузка модели, телефонный адрес и другие созданные владельцем медиа могут требовать сеть.

## Отдельные интеграционные фикстуры

Существующие integration suites намеренно очищают только свою БД с защитными проверками имени/порта. Их нельзя направлять на демо курс. Для них предусмотрен второй отмеченный disposable профиль `.local/release-tests` с PostgreSQL:55432 / `proctolearn_security_test` и S3:19000:

```powershell
node scripts/demo-release-tests.cjs start
# Во втором терминале, последовательно:
node scripts/demo-release-tests.cjs run backend test:migrations
node scripts/demo-release-tests.cjs run backend test:integration
node scripts/demo-release-tests.cjs run backend test:storage
node scripts/demo-release-tests.cjs stop
```

Runner передаёт приватные TEST_* переменные дочернему процессу и блокирует параллельные группы через `suite.lock`. Для отдельного файла: `node scripts/demo-release-tests.cjs exec backend --require ts-node/register test/integration/ai-access.test.cjs`. Не выполняйте одновременно `npm ci` и тесты/сборку того же каталога. Если процесс runner аварийно завершился, сначала убедитесь, что PID из приватного lock больше не существует; автоматическое снятие чужого lock не выполняется.

Для E2E на работающем выделенном release профиле используйте `node scripts/demo-release.cjs exec frontend e2e/stage9.cjs`. Команда передаёт только его конфигурацию через `E2E_ENV_FILE`; путь/ownership marker проверяются сценарием. При необходимости явно задайте путь к установленному Chrome в `E2E_CHROME_PATH`.

В новых профилях SeaweedFS запускается через `server -filer -s3` с приватной IAM-конфигурацией, durable leveldb и loopback listeners. `mini -admin.ui=false` версии 4.47 всё равно запускает admin gRPC на wildcard: поэтому mini не используется для release и integration профилей. Старый `.local` путь не мигрируется автоматически.

Точные выполненные проверки и фактический SHA фиксируются в `docs/TEST_RESULTS.md` и `docs/DEMO_READINESS.md`; этот runbook сам по себе не свидетельство успешного запуска или полной готовности.
