# UX-01: политика регистрации

20.10.2026. Добавлен GET `/auth/registration-policy`: `{registrationOpen, invitationRequired}` от существующего server PilotService.enabled, Cache-Control no-store. Публичный ответ содержит только две возможности, без персональных данных/токенов. POST register/DTO/cookies/CSRF/роль STUDENT не изменены. Consumers: новый hook `use-registration-policy.ts`, форма регистрации и landing (подключение следующим шагом). Ошибка чтения не трактуется как разрешение регистрации. Проверки: NOT_RUN до подключения потребителей/тестов.

Следующая правка: hook подключён к главной/CTA/форме. Closed pilot объяснён до полей, код required/password, не попадает в URL/storage; перед отправкой проверяется текущая полученная политика. Open mode сохраняет обычную форму. При недоступной политике форма не показывается, есть retry и каталог. Регистрация использует прежний authMutation с CSRF. Маршрут proxy добавляется владельцем UX-04. Изменены page.tsx, auth/register/page.tsx, PremiumSections.tsx. Проверки NOT_RUN (ожидается общая сборка после параллельных изменений).

Добавлены regression tests backend/test/registration-policy.test.cjs: обе server policies, no-store response, отказ closed registration без приглашения до любых записей. Выполнение ожидается следующим шагом; реальных аккаунтов эти тесты не создают.

Проверка выполнена: `node --require ts-node/register test/registration-policy.test.cjs` (backend) — PASSED, 2/2. Browser формы, интеграция proxy и полный build ожидают финального artifact. Это не проверка физического телефона.
