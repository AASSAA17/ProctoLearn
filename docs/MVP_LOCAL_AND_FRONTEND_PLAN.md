Проверено 28.09.2026 в `C:\Users\Arsen\ProctoLearn`. Это рабочий план развития продукта, а не заявление, что каждая функция готова к публичному запуску.

## Что запускается сейчас

`start-local.cmd --native --demo-minimal` или Docker-вариант без `--native` поднимает сайт, API, отдельные PostgreSQL и S3. Адреса: `http://localhost:3000`, `http://localhost:4000/ready`. Новая пустая база получает четыре учебные роли, один курс, урок и экзамен. Пароли остаются в приватном `.local/DEMO_ACCESS.txt`. Без флага demo данные не добавляются. `--demo` оставлен для большого учебного набора. Повторный запуск **не удаляет** существующие данные; поэтому в уже использованной `.local` могут оставаться прежние 54 курса.

На этой машине локальный API вернул `ready`, каталог — 54 курса до нового минимального seed, страница входа — HTTP 200. Последний CI для `main` до текущих правок проверил сборки, PostgreSQL/S3 и браузерный сценарий четырёх ролей. Физическая камера, системный выбор экрана и эксплуатация на публичном домене этим не подтверждаются.

## Кнопки и блоки до работы дизайнера

- Оставить на главной две понятные цели: посмотреть реальные курсы и войти/зарегистрироваться. «Курстар», «Мүмкіндіктер» в широком меню — навигация по странице; на мобильном его пока скрыли ради рабочей ширины. Дизайнеру подготовить компактное мобильное меню после определения публичного каталога.
- Карточки технологий сейчас информационные. Делать их кнопками снова только когда будет фильтр по технологиям, а не переход на общую регистрацию.
- Кнопка после девяти карточек теперь открывает полный каталог. Повторный призыв к регистрации внизу страницы оценить после наблюдения за первым пользовательским сценарием.
- Админ-экспорт пользователей/курсов доступен с нескольких страниц. Определить одно постоянное место после проверки работы сотрудников, чтобы не загромождать главный экран.
- Плавающий AI-чат сейчас даёт локальные ответы без внешнего ключа; решать, нужен ли он первому выпуску, после проверки реальных вопросов учащихся и правил передачи данных внешнему AI.
- Отзывы, цифры успеха, «официальный» сертификат, адрес поддержки и обещание трудоустройства не возвращать без подтверждённых источников и владельца контента.

## Последовательность дальнейших работ

Проверки по ролям сейчас включают вход четырёх аккаунтов, пункты навигации, отказ на чужой URL, запрет записи на курс для сотрудников и сценарии 503 → повтор для рабочих страниц. Браузерный smoke с автоматической проверкой WCAG A/AA проходит профиль, результаты, сертификаты, форму нового курса, проктор-панель, админ-страницы и уведомления каждой роли. Отдельный браузерный сценарий создаёт и удаляет курс, раздел и урок от учителя, сверяет связи в БД и запрещает создание проктору; временные данные очищаются. Проверки администратора подтверждают, что выдача доступа сотруднику возвращает 403 без новой записи, а сбои списка пользователей и выбора курса можно повторить. Исправлены обнаруженные подписи полей и контраст текста. Для требования «тесты везде» ещё нужны сценарии изменения существующего экзамена и его вопросов, уведомлений, изменения ролей/паролей администратором и ручная проверка камеры/экрана на реальных устройствах. Зелёная сборка не заменяет эти проверки.

1. **Локальный MVP:** проверить минимальный seed на новой изолированной БД, вход всех четырёх ролей, урок → экзамен → запись → решение проктора → сертификат. Исправить P1 состояния ошибок и добавить браузерный тест главной на 390/768 px. Критерий: пользователь видит причину сбоя и может повторить действие; каталог не притворяется пустым при 5xx.
2. **Контент и публичный каталог:** выбрать реальные 1–3 курса, заполнить уроки и вопросы, убрать заглушки из публичных данных. Сделать URL и пагинацию для каталога, чтобы карточка курса открывала его описание до регистрации. Критерий: каждый видимый курс содержит проверенный материал и ясное действие.
3. **Дизайн после стабильной логики:** единый язык, информационная архитектура ролей, мобильная навигация, сокращение повторных CTA, единые состояния loading/empty/error, проверка контраста и ручная доступность. Критерий: основные сценарии понятны на телефоне и десктопе без объяснений разработчика.
4. **Публичный пилот:** отдельный сервер/хостинг, постоянные PostgreSQL/S3, домен и DNS, HTTPS для сайта/API/storage, приватные ключи, SMTP, backup и проверка восстановления, защита demo-аккаунтов. Домен сам по себе приложение не размещает. Проверки и возврат описаны в [RELEASE_RUNBOOK.md](RELEASE_RUNBOOK.md). Критерий: зелёный CI того же SHA, staging и ручной прогон устройств, затем согласованное переключение.
5. **После пилота:** измерять время загрузки, ошибки, потребность в AI и прокторинге; добавлять функции по обратной связи, а не по одному макету. Автоматическое распознавание лица/телефона требует отдельной оценки точности, ложных срабатываний и приватности.

Старые личные отчёты от 15.09.2026 отражают прежнее состояние (до работающего локального запуска и тестов); их записи `BLOCKED` и «нет test script» не следует считать текущими дефектами. Они сохранены без изменения.
