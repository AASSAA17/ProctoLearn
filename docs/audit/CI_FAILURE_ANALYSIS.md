## CI-001 — E2E не имитировал отказ API после добавления query-параметров

- **Приоритет:** P0 для ветки `fix-p2-batch3`.
- **Компонент:** Playwright E2E.
- **Файл:** `frontend/e2e/stage9.cjs`.
- **Проявление:** ожидание alert `Курстарды жүктеу мүмкін болмады.` завершалось по таймауту.
- **Воспроизведение:** в версии `939647b` открыть страницу администратора пользователей в E2E. Компонент отправляет `GET /courses?page=1&limit=20`, тогда как route matcher теста был `**/courses`.
- **Первопричина:** в Playwright glob соответствует полному URL. Matcher без query string не перехватывает пагинированный запрос, поэтому сервер отдаёт обычный успешный ответ, `coursesError` остаётся `false`, а ожидаемый alert не рендерится.
- **Исправление:** matcher заменён на predicate, сравнивающий origin API и `pathname === '/courses'`. Он покрывает запрос как с query-параметрами, так и без них. Assertion и timeout не изменялись.
- **Дополнительная стабилизация:** тест доступности регистрации больше не полагается на состояние demo seed, в котором студент уже записан на единственный курс. Перед проверкой он создаёт изолированный незаписанный курс.
- **Проверка:** `E2E_DISPOSABLE=true node frontend/e2e/stage9.cjs` успешно выполнена дважды на локальном изолированном PostgreSQL, API, web и S3-совместимом хранилище. `npm run typecheck` в `frontend/` завершилась успешно.
